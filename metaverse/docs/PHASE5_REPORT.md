## 1. 45人規模の同時接続（負荷テスト）

`node tools/loadtest.js` で何度でも再実行できます。

**条件**：先生3人＋生徒45人が同時に接続し、3つの教室に15人ずつ実際の歩く速さで入って着席します。3教室で授業を開始したあと、60秒間の授業中の動きを再現しました。

- 毎秒、生徒の約2％が挙手を切り替え、約2％がリアクションを送る
- 常に6人が教室内を歩き回る

| 項目 | 改善前 | 改善後 |
| --- | --- | --- |
| 入室・着席 | 48/48人 成功 | 48/48人 成功 |
| 定員どおりの入室（各教室15/15） | ○ | ○ |
| 拒否された移動（誤判定） | 0 | 0 |
| 位置同期の遅延（中央値 / 99%） | 2.0 / 4.6 ms | 34.5 / 66.8 ms ※ |
| サーバーのCPU使用率 | 3.8 % | **1.8 %** |
| サーバーのメモリ | 124 MB | 114 MB |
| **生徒1人あたりの受信量** | 6.8 KB/秒（84通/秒） | **1.3 KB/秒（12通/秒）** |

※ 改善後は、位置の更新を0.1秒ごとにまとめて送る方式に変えました。そのため遅延は増えています（最大でも0.1秒程度）。アバターはなめらかに動くよう補間しているため、見た目の違いはほとんどありません。

**わかったこと**
- 45人規模では、サーバーの性能に十分な余裕があります。いちばん安いクラスのサーバーでも足ります。
- 改善前は、アバターの移動だけで**1時間あたり約24MB**をスマホが受信していました。改善後は**約5MB**です。
- 音声・画面共有は LiveKit Cloud が中継するため、このサーバーの負荷には含まれません。LiveKit 側の負荷と通信量は、本番前の実機チェックで LiveKit のダッシュボードを見て確認してください。

**計測の限界**
- テスト用の参加者とサーバーを同じコンピューターで動かしています。
- 実際のインターネットの遅延（数十〜百数十ms）は含みません。

## 2. セキュリティ点検

`npm test` に含まれる `test/security.test.js` で、10項目を自動で確認しています。

| 点検項目 | 結果 | 対応 |
| --- | --- | --- |
| ログイン認証・パスワード保存（scrypt） | ○ | 第1段階から |
| 管理機能・入室・通話の権限をサーバー側で確認 | ○ | 権限関連テスト 計56項目 |
| 生徒からほかの人への個別通話の開始 | 不可（機能自体なし） | 第4段階から |
| 許可のない通話・画面共有の送信 | 不可（トークンで制限） | 第3・4段階から |
| 録音・録画 | 行わない（録画権限をトークンに付けない） | 第3段階から |
| 不正な HTML・スクリプトの埋め込み | 防止（`<>` を除去、画面は文字として表示、CSPでインラインスクリプト禁止） | テスト追加 |
| 他サイトからの操作・埋め込み | 防止（Origin 確認、SameSite Cookie、frame-ancestors none） | テスト追加 |
| 大きすぎる・壊れたリクエスト | 拒否（413/400/415）、サーバーは停止しない | テスト追加 |
| ログインの総当たり | 同じIDで5回失敗すると15分ロック | 第1段階から |
| **パスワード変更の総当たり** | **ロックがなかった → 5回失敗で15分ロックを追加** | 今回修正 |
| **リアルタイム通信の連打（大量送信）** | **移動以外は制限がなかった → 1人あたり平均10回/秒までに制限** | 今回修正 |
| **挙手の連打で先生に通知が大量に届く** | **制限がなかった → 手をあげるのは3秒に1回まで** | 今回修正 |
| 授業中のマイク・画面共有状態の連打 | **0.3秒に1回までに制限** | 今回修正 |
| **操作ログ（IPアドレスを含む）がずっと残る** | **180日で自動削除するように変更**（`AUDIT_RETENTION_DAYS` で変更可） | 今回修正 |
| 生徒の画面にほかの人のログインID・IPが届かない | ○ | テスト追加 |
| 依存ライブラリの既知の脆弱性（npm audit） | 0件 | ― |
| 不審な接続の停止 | オーナーが切断・ログアウト・無効化できる | 第2段階から |
| 通信の暗号化 | 本番は HTTPS 必須（`NODE_ENV=production` で Cookie を HTTPS 専用に）。LiveKit は常に暗号化（DTLS-SRTP） | 公開時に設定 |

**運用で注意すること**
- 本番では必ず `NODE_ENV=production` と `TRUST_PROXY=1` を設定してください。
- `LIVEKIT_API_SECRET` は、公開先の「環境変数」画面にだけ入力してください。
- 生徒の表示名は、名字だけやニックネームにすることをおすすめします。
- サーバーは **1台で運用**してください。入室状況はサーバーのメモリで管理しているため、2台以上に増やすと人数が正しく数えられません。45人規模なら1台で十分です。

## 3. スマホでの操作性

`tools/mobilecheck.js` で7機種の画面を再現し、ボタンの重なり・画面外へのはみ出し・押しにくい小さなボタン（44px未満）を自動で調べました。

| 機種（再現） | 改善前 | 改善後 |
| --- | --- | --- |
| iPhone SE（320×568） | 部屋名が2行に折り返し・名前ボタンがつぶれる | 問題なし |
| iPhone 13 / 15 Pro Max | 名前ボタンが小さい（38px） | 問題なし |
| Pixel 7 / Galaxy S9+ | 名前ボタンが小さい | 問題なし |
| iPhone 横向き（750×342） | 名前ボタンが小さい | 問題なし（横向きでは「テスト版」表示を隠し、スティックを小さく） |
| iPad mini | 名前ボタンが小さい | 問題なし |

**このほかに追加した改善**
- **画面の自動消灯を防ぐ**：授業中と個別通話中は、画面が消えないようにしました。画面が消えると音が止まる端末があるためです（iOS 16.4以降・Android Chrome で有効）。
- **🔈 音のテスト**：右上の名前ボタンのメニューから、スピーカーやイヤホンから音が出るかを生徒が自分で確かめられます。聞こえない場合は、マナーモードの確認を案内します。
- **通信が不安定なときの表示**：「⚠️ 通信が不安定です。Wi-Fi の近くへ移動してみてね」と表示します。
- 「テスト版」の表示は、タップで消せます。

## 4. 音声品質と通信量

LiveKit の送信設定を、授業向けに調整しました（授業・個別通話の両方）。

| 設定 | 内容 | 理由 |
| --- | --- | --- |
| 音声 | 声向けの設定（約24kbps）。初期設定の音楽向けは約48kbps | 話し声には十分な音質で、通信量は約半分 |
| RED（音声の予備送信） | 有効 | スマホ回線で音が途切れにくくする |
| DTX（無音時は送らない） | 有効 | 先生が話していないときの通信量を減らす |
| 画面共有 | 最大1.2Mbps・8コマ/秒。スマホには文字が読める720p（5コマ/秒）を配信 | 黒板・資料は文字の読みやすさ優先で、動きは少なくてよい |

**生徒のスマホの通信量の目安（1時間の授業）**
- 先生の声だけ：約10MB
- アバターの動き：約5MB
- 先生の画面共有を見る：**最大で約360MB**。資料がほとんど動かなければ、これより大幅に少なくなります。
- → 画面共有を多く使う授業は、**Wi-Fi での参加を案内**してください。

## 7. 公開（本番運用）の手順の目安

> **更新（2026-11-16）**：無料で運用する方法を追加しました。手順は [GETTING_STARTED.md](GETTING_STARTED.md) を参照してください（Render 無料プラン＋Neon 無料プラン＋LiveKit 無料枠）。データは Neon に自動保存されるため、無料プランの再起動でも消えません。以下は有料プラン（ディスク付き）で運用する場合の参考です。


1. **Render などの Node.js が動くサービス**にデプロイします（Netlify は不可）。
   - 起動コマンド：`npm start`
   - 環境変数：`NODE_ENV=production`、`TRUST_PROXY=1`、`LIVEKIT_URL`、`LIVEKIT_API_KEY`、`LIVEKIT_API_SECRET`
2. **データの保存先**：SQLite のファイル（`DB_PATH`）は、再起動しても消えない保存場所（Render の Persistent Disk など）に置きます。PostgreSQL への移行も可能です。
3. **バックアップ**：データベースのファイルを1日1回コピーします（ユーザー・権限・設定のみで、容量はごく小さい）。
4. **サーバーは1台で運用**します（上記の注意を参照）。
5. 独自ドメインを使う場合は、HTTPS 証明書が自動で発行されることを確認します。
